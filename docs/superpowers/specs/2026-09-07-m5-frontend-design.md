# M5 · 프론트엔드/UX — 설계

원본 스펙은 Notion `M5 · 프론트엔드/UX`. 이 문서는 그 스펙을 이 저장소의
구현 결정으로 옮긴 것이며, 노션이 확정한 디자인 시스템·화면 구성·완료기준을
다시 적지 않는다. 여기 적는 것은 **노션이 "결정 필요"로 남긴 것들과, 스펙을
코드에 대보고 나서야 드러난 것들**뿐이다.

## 확정된 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 프론트 스택 | Next.js 15 App Router + TypeScript + Tailwind | 노션 추천. 백엔드가 이미 CORS를 `:3000`으로 열어둠 |
| 컴포넌트 라이브러리 | **shadcn/ui 쓰지 않음** | 아래 참조 |
| 스타일링 | CSS 변수(토큰) + Tailwind(레이아웃 전용) | 토큰이 라이트/다크 양쪽으로 확정돼 있어 변수가 원본, Tailwind는 배치만 |
| 멀티턴 맥락 | A안 — 각 질문 독립 | 백엔드에서 이미 채택됨 (`conversations.py` 참조) |
| 프론트 위치 | 저장소 안 `web/` | 백엔드와 한 저장소, 배포는 M6에서 분리 |

### shadcn/ui를 쓰지 않는 이유

디자인 시스템이 색 토큰·1px 테두리·radius·각주 상자(15px 정사각, radius 3px,
호버 시 반전)까지 픽셀 단위로 확정돼 있다. shadcn을 넣으면 기본 스타일을
걷어내는 작업이 직접 만드는 것보다 커진다. 모달 접근성(포커스 트랩·ESC·aria)은
M5 "공부할 것"에 명시된 항목이라 직접 구현하는 편이 목적에도 맞다.

## 백엔드 갭 (P0)

스펙의 화면 요구를 현재 API에 대보고 나온 두 건. 이게 없으면 완료기준을
정직하게 만족시킬 수 없다.

### 1. `GET /chunks/{chunk_id}`

근거 모달은 "문서명 · 페이지 · **청크 원문**"을 보여야 한다. 그런데
`Citation.snippet`은 `generate._snippet()`이 240자에서 자르고 `…`을 붙인
값이다. 잘린 스니펫으로는 "해당 청크를 정확히 표시"했다고 할 수 없다.

소유자 한정으로 청크 원문을 돌려주는 라우트를 추가한다. 남의 청크는 403이
아니라 404 — 문서 API와 같은 규칙.

문서명은 `document_id` → `GET /documents` 조인으로 프론트에서 해결되므로
응답에 넣지 않는다.

### 2. `GET /usage`

설정 화면의 사용량 바가 "82쪽 남았습니다" 같은 문장을 쓰려면 현재 사용량과
한도가 필요하다. `usage.queries_today()` / `usage.pages_this_month()` 헬퍼는
이미 있고 라우트만 없다.

## 구현하면서 걸리는 지점

노션 스펙이 다루지 않았고, 코드를 보고 나서야 드러난 것들.

### SSE에 `EventSource`를 쓸 수 없다

`POST /conversations/{id}/query`는 본문이 있고 세션 쿠키가 필요하다.
`EventSource`는 GET 전용이고 본문을 실을 수 없다. `fetch` + `ReadableStream`
으로 `event:` / `data:` 프레임을 직접 파싱한다 (`lib/sse.ts`).

### `error` 이벤트가 HTTP 200 안에서 온다

스트리밍이 시작되면 상태 코드는 이미 200으로 확정된다. 백엔드는 그래서
429(쿼터)·500을 `event: error`의 본문으로 보낸다 (`conversations.py` 참조).
프론트는 **상태 코드가 아니라 이벤트를 보고** 쿼터 안내·재시도를 띄워야 한다.

### 각주 매핑은 역매칭이다

LLM은 답변 본문에 `[p.5]`를 쓰고, `citations[]`는 그와 별개인 배열이다.
둘을 잇는 것은 페이지 번호뿐이다. 렌더 시 `[p.N]`을 위첨자 번호로 치환하면서
`page_from`(범위 청크면 `page_from~page_to`)으로 citation을 역매칭한다.

매칭 실패(모델이 컨텍스트에 없는 페이지를 인용)는 실제로 일어날 수 있다.
그 경우 각주 번호를 만들지 않고 `[p.N]` 텍스트를 그대로 둔다 — 클릭했는데
빈 모달이 열리는 것보다 낫다.

### 거부(refused) 답변은 각주가 없다

백엔드가 거부를 감지하면 citations를 비운다. 프론트는 거부를 답변이 아니라
알림 블록으로 렌더하고, 스펙의 카피 규칙대로 다음 행동을 제안한다
("전체 문서에서 다시 찾기").

## 단계

| 단계 | 내용 |
|---|---|
| P0 | 백엔드 갭 2개 (`/chunks/{id}`, `/usage`) + 테스트 |
| P1 | 스캐폴드 · 디자인 토큰 · 프리미티브(각주·상태표시·알림블록·버튼·모달) |
| P2 | API 레이어 + 로그인 화면 |
| P3 | 문서 — D&D 업로드 · 목록 · 상태 폴링 · 상세 |
| P4 | 채팅 — 대화 목록 · SSE 스트리밍 · 각주 · 근거 모달 · 범위 전환 |
| P5 | 설정(테마·사용량·계정) · 반응형 · 완료기준 점검 |

## 미해결 (노션에서 이월)

**위험 동작 시각 구분.** 색을 없애면서 '계정 지우기'가 일반 버튼과 같아졌다.
P5에서 확인 모달 한 단계를 넣는 쪽으로 간다 — 색 없이 "돌이킬 수 없다"를
전달하는 건 형태보다 문구와 마찰이다.
